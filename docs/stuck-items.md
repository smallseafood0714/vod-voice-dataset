## [ ] 筆電的 RTX 4060 一有負載就掉卡，訓練要用的 GPU 沒著落

- **日期**：2026-10-30
- **現象**：人聲分離用 GPU 跑幾分鐘就掉卡，接著藍屏（0x113）。外接螢幕偶爾黑掉、重插 HDMI 也救不回來，可能是同一個問題。
- **證據**（`scripts/gpu_stress.py`，紀錄在 `logs/gpu_stress_*.csv`，不進 git）：
  - 滿載 5 秒就掉卡：`CUDA error: unknown error`，nvidia-smi 顯示 `GPU is lost`，要重開機才會恢復。
  - 同一秒 Windows 系統紀錄有 WHEA-Logger 事件 17，來源是 PCI Express Root Port（`VEN_8086&DEV_A70D`）。
    也就是 CPU 和顯示卡之間的 PCIe 連線出錯，不是過熱。
  - 驅動從 610.60 更新到 617.42 後重測，一樣在 19 秒內掉卡，同樣有 WHEA 事件。
  - 剛開機、還沒有負載時也記到 3 筆 WHEA 事件，所以不只是負載的問題，比較像硬體或韌體。
- **目前的處置**：清洗的第 1～5 步都改成只用 CPU（第 2 步加 `--cpu`，其他步驟本來就只用 CPU），資料清洗不受影響。
- **擋到什麼**：下一階段的 TTS 訓練（GPT-SoVITS）實際上一定要 GPU。
- **還沒試的方向**（系統設定與韌體要你自己動手）：
  - 到筆電廠商網站更新 BIOS / EC 韌體和 Intel 晶片組驅動。
  - Windows 電源選項 → PCI Express → 連結狀態電源管理改成「關閉」。PCIe 省電狀態切換出錯是 WHEA 17 的常見原因。
  - 還在保固內的話送修，附上 WHEA 事件和壓力測試的 CSV。
  - 以上都不行：訓練改租雲端 GPU（Colab、RunPod 之類），資料清洗繼續在這台用 CPU 做。
- **要你拍板**：先修筆電，還是直接規劃租雲端 GPU 來訓練。
